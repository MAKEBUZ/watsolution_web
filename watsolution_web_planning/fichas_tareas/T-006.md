# [T-006] Persistir únicamente la clave PDF de la factura

- **Hallazgos que resuelve:** WS-002. Resuelve la parte descrita; el hallazgo completo exige todas sus tareas de corrección en la matriz.
- **Prioridad / Fase / Esfuerzo:** P0 / F1 Contención inmediata / 8–12 h-persona. Estado: Pendiente. Responsable sugerido: Backend / líder técnico, nombre por asignar.
- **Contexto y riesgo si no se corrige:** Generar el PDF puede deshacer un pago concurrente. La descarga permitida al propietario carga una factura PENDING, espera PDF/S3 y guarda la copia completa. Si el webhook confirma PAID durante la espera, InvoiceService.update vuelve a guardar PENDING y puede borrar la referencia de pago de una instantánea antigua.
- **Archivos y líneas afectados:**

- Evidencia: WS-002: server/src/web/rest/invoice.controller.ts:101.
- Cambio previsto o referencia operativa: server/src/web/rest/invoice.controller.ts.
- Cambio previsto o referencia operativa: server/src/service/invoice.service.ts.

Los archivos bajo reportes se citan solo como evidencia y nunca son destino de implementación. Las rutas marcadas nuevas no existen todavía. Las líneas son del estado revisado y se ubican de nuevo antes de implementar.

- **Pasos de implementación (numerados):**

1. Añadir actualización parcial de pdfUrl por ID.
2. Sustituir ambos guardados de instantánea en descarga y generate-pdf.
3. Inyectar barrera S3 durante confirmación de pago y probar errores de generación.

- **Ejemplo de código antes/después (si aplica):**

Esquema orientativo; no es un parche aplicado. Nombres nuevos requieren implementación y pruebas.

Antes:

```ts
await this.invoiceService.update({ ...invoice, pdfUrl: pdfKey });
```

Después:

```ts
await this.invoiceService.updatePdfKey(invoice.id, pdfKey);
// UPDATE parcial: { pdfUrl: pdfKey }; no transportar status ni pagos.
```

- **Plan de rollback:** Desactivar regeneración PDF y servir documentos existentes; conservar estado financiero y no volver al guardado completo.
