# [T-005] Aislar el portal mediante el ID autenticado

- **Hallazgos que resuelve:** WS-001. Resuelve la parte descrita; el hallazgo completo exige todas sus tareas de corrección en la matriz.
- **Prioridad / Fase / Esfuerzo:** P0 / F1 Contención inmediata / 8–16 h-persona. Estado: Pendiente. Responsable sugerido: Backend / líder técnico, nombre por asignar.
- **Contexto y riesgo si no se corrige:** El portal confunde el login con el propietario y permite cruzar cuentas. El controlador pasa req.user.login (portal.controller.ts:24), pero person.userId contiene el ID convertido a texto (person.controller.ts:127). Una cuenta activada con login numérico igual al ID de otra cuenta puede obtener su perfil y facturas. La alternativa por email también es ambigua. No se probó acceso a datos reales.
- **Archivos y líneas afectados:**

- Evidencia: WS-001: server/src/service/portal.service.ts:25.
- Cambio previsto o referencia operativa: server/src/service/portal.service.ts.
- Cambio previsto o referencia operativa: server/src/web/rest/portal.controller.ts.
- Cambio previsto o referencia operativa: server/src/domain/person.entity.ts.

Los archivos bajo reportes se citan solo como evidencia y nunca son destino de implementación. Las rutas marcadas nuevas no existen todavía. Las líneas son del estado revisado y se ubican de nuevo antes de implementar.

- **Pasos de implementación (numerados):**

1. Cambiar controlador para pasar req.user.id.
2. Consultar Person por String(id) sin alternativa por login o correo; denegar vínculos ausentes/ambiguos.
3. Crear prueba de dos cuentas con login numérico coincidente y comprobar perfil, facturas y resúmenes.

- **Ejemplo de código antes/después (si aplica):**

Esquema orientativo; no es un parche aplicado. Nombres nuevos requieren implementación y pruebas.

Antes:

```ts
return this.portalService.getPortalData(req.user?.login);
```

Después:

```ts
return this.portalService.getPortalDataByUserId(req.user.id);
// Servicio: where: { userId: String(userId) }; sin fallback por correo.
```
