# [T-007] Limpiar el chat cuando cambia la sesión

- **Hallazgos que resuelve:** WS-006. Resuelve la parte descrita; el hallazgo completo exige todas sus tareas de corrección en la matriz.
- **Prioridad / Fase / Esfuerzo:** P0 / F1 Contención inmediata / 4–8 h-persona. Estado: Pendiente. Responsable sugerido: Frontend Vue, nombre por asignar.
- **Contexto y riesgo si no se corrige:** El historial del chatbot sobrevive al cambio de usuario. App monta ChatBot permanentemente (app.vue:8). El logout solo lo oculta mediante hidden; messages no se limpia ni se vincula a la identidad. En el mismo navegador, la siguiente cuenta puede ver cédulas y resúmenes consultados por la anterior. Una respuesta en vuelo también puede agregarse tras el cambio.
- **Archivos y líneas afectados:**

- Evidencia: WS-006: client/src/app/core/chatbot/chatbot.vue:26.
- Cambio previsto o referencia operativa: client/src/app/core/chatbot/chatbot.vue.
- Cambio previsto o referencia operativa: client/src/app/app.vue.

Los archivos bajo reportes se citan solo como evidencia y nunca son destino de implementación. Las rutas marcadas nuevas no existen todavía. Las líneas son del estado revisado y se ubican de nuevo antes de implementar.

- **Pasos de implementación (numerados):**

1. Desmontar o reiniciar el chat por identidad de sesión.
2. Borrar mensajes, entrada y estados; abortar petición o descartar respuesta de sesión anterior.
3. Probar salida y cambio admin a usuario con respuesta en vuelo.

- **Ejemplo de código antes/después (si aplica):**

Esquema orientativo; no es un parche aplicado. Nombres nuevos requieren implementación y pruebas.

Antes:

```ts
const messages = ref<Msg[]>([]); // vive más que la sesión
```

Después:

```ts
// Pseudocódigo: usar ID de sesión y generación de petición.
watch(sessionIdentity, () => {
  generation++; controller?.abort(); messages.value = [];
  input.value = ""; loading.value = false;
});
// Antes de publicar respuesta: comprobar generación e identidad.
```
