# [T-016] Conciliar vínculos de usuarios y suscriptores

- **Hallazgos que resuelve:** WS-001, WS-015. Resuelve la parte descrita; el hallazgo completo exige todas sus tareas de corrección en la matriz.
- **Prioridad / Fase / Esfuerzo:** P1 / F2 Estabilización / 16–24 h-persona. Estado: Pendiente. Responsable sugerido: Backend / líder técnico, nombre por asignar.
- **Contexto y riesgo si no se corrige:** El portal confunde el login con el propietario y permite cruzar cuentas. El controlador pasa req.user.login (portal.controller.ts:24), pero person.userId contiene el ID convertido a texto (person.controller.ts:127). Una cuenta activada con login numérico igual al ID de otra cuenta puede obtener su perfil y facturas. La alternativa por email también es ambigua. No se probó acceso a datos reales. Los vínculos de identidad son columnas sin integridad referencial. user_id es texto libre y assigned_operator_id un entero sin relación/FK declarada. Sesiones y operaciones también guardan IDs sin FK en su migración. Borrar una cuenta puede dejar suscriptores, sesiones o asignaciones huérfanos; el código alterna interpretaciones de identidad.
